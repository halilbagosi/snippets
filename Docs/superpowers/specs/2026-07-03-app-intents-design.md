# App Intents Integration — Design

**Date:** 2026-07-03
**Status:** Approved (design), pending implementation
**Scope:** Add App Intents to Snippets (macOS 26+, SwiftData) so snippets and
collections are actionable from Shortcuts, Siri, and Spotlight.

## Goal

Expose the app's core actions and data to the system App Intents framework,
following Apple's guidelines: model app data as `AppEntity` types with queries,
expose actions as focused `AppIntent`s, and register a small set of
`AppShortcuts` phrases. No changes to existing in-app behavior beyond a single
navigation hook.

## Constraints & context

- **Platform:** macOS 26+, SwiftData (`Snippet`, `SnippetCollection`,
  `MediaItem`). Single local store at
  `applicationSupportDirectory/Snippets.store`. No CloudKit sync.
- **Build:** App Intents *metadata* (what lets Shortcuts/Siri/Spotlight
  discover intents) is generated by Xcode's build step, not plain
  `swift build`. Distribution builds go through the `.swiftpm/xcode` workspace,
  which generates the metadata. Code compiles under both.
- **Toolchain:** builds/tests require the Xcode-beta toolchain
  (`DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer`); unit tests
  run via `swift test`.
- **No existing App Intents** in the codebase prior to this work.

## Architecture

New tree under `Sources/Snippets/Intents/`, plus two small touch-points in
existing files.

```
Sources/Snippets/Intents/
  SnippetsData.swift              // shared ModelContainer (extracted from SnippetsApp)
  AppIntentNavigator.swift        // @Observable bridge: intent -> ContentView selection
  SnippetQueryFilter.swift        // pure, testable filtering logic
  Entities/
    SnippetEntity.swift           // AppEntity + SnippetEntityQuery (EntityStringQuery)
    SnippetCollectionEntity.swift // AppEntity + SnippetCollectionEntityQuery
  Actions/
    CopySnippetIntent.swift
    CreateSnippetIntent.swift
    OpenSnippetIntent.swift
    FindSnippetsIntent.swift
    ToggleFavoriteSnippetIntent.swift
  SnippetsAppShortcuts.swift      // AppShortcutsProvider
```

Touch-points in existing files:

- `SnippetsApp.swift` — use `SnippetsData.sharedModelContainer` instead of an
  inline container; inject `AppIntentNavigator` into the environment; run the
  UUID backfill on launch.
- `ContentView.swift` — one `.onChange` observing `AppIntentNavigator` to open a
  requested snippet.
- `Models/Snippet.swift`, `Models/Collection.swift` — add `var uuid: UUID?`.

## Decision 1 — Stable entity identity

Shortcuts persist an entity's `id` inside saved shortcuts, so it must be stable
across launches. `PersistentIdentifier` is store-relative and fragile for this.

**Chosen:** add `var uuid: UUID?` to `Snippet` and `SnippetCollection`.

- New rows get a UUID at `init` (default `UUID()` in the initializer).
- Existing rows are **optional (`UUID?`)** to keep SwiftData lightweight
  migration trivially safe (existing rows migrate to `nil`), avoiding the
  non-optional `= UUID()` case where a single evaluated default could be shared
  across rows.
- A backfill assigns UUIDs to any `nil` rows:
  - on app launch (one pass over snippets + collections), and
  - lazily inside entity queries / when building an entity from a model, so an
    intent that runs before the app has launched post-update still gets stable
    ids.
- `AppEntity.id` is the (backfilled) UUID.

Helper on each model (or a small free function): `ensureUUID(in context:) -> UUID`
that assigns and saves if `uuid == nil`, returns the value.

## Decision 2 — Shared ModelContainer

Intents can run while the app is backgrounded and need the same store as the UI.
Two containers pointed at one store URL would conflict.

**Chosen:** extract the inline `sharedModelContainer` from `SnippetsApp` into a
single static:

```swift
enum SnippetsData {
    @MainActor static let sharedModelContainer: ModelContainer = { /* same logic */ }()
}
```

`SnippetsApp` references `SnippetsData.sharedModelContainer`. Every intent uses
`SnippetsData.sharedModelContainer.mainContext` and is annotated `@MainActor`.

## Entities

### SnippetEntity: AppEntity

- `id: UUID` (backfilled from the model).
- `@Property` exposed fields: `title`, `language`, `code` (display-truncated),
  `isFavorite`.
- `typeDisplayRepresentation = "Snippet"`.
- `displayRepresentation`: title (fallback "Untitled") as the title, language as
  subtitle.
- `static var defaultQuery = SnippetEntityQuery()`.

**SnippetEntityQuery: EntityQuery, EntityStringQuery**

- `entities(for identifiers: [UUID]) -> [SnippetEntity]` — fetch non-deleted
  snippets whose `uuid` is in the set.
- `suggestedEntities() -> [SnippetEntity]` — recent non-deleted snippets
  (sorted by `updatedAt`, capped, e.g. 10).
- `entities(matching string:) -> [SnippetEntity]` — title/description match,
  reusing `SnippetQueryFilter`.

### SnippetCollectionEntity: AppEntity

- `id: UUID`, `@Property name`, icon/color are not needed as properties.
- `typeDisplayRepresentation = "Collection"`; `displayRepresentation` = name.
- `SnippetCollectionEntityQuery: EntityQuery` with `entities(for:)` and
  `suggestedEntities()` (non-deleted collections).

Both queries exclude soft-deleted rows (`deletedAt != nil`).

## Intents

All are `@MainActor`, use `SnippetsData.sharedModelContainer.mainContext`.

| Intent | title | openAppWhenRun | Parameters | Result |
|---|---|---|---|---|
| **CopySnippetIntent** | "Copy Snippet Code" | false | `snippet: SnippetEntity` | copies `code` to clipboard via `Clipboard.copy`, increments `copyCount`, saves. Returns `code` (`ReturnsValue<String>`) + dialog "Copied \(title)". |
| **CreateSnippetIntent** | "Create Snippet" | false | `title: String`, `code: String`, `language: String?` (default "Unknown"), `collection: SnippetCollectionEntity?` | inserts snippet (with UUID + optional collection membership), saves. Returns new `SnippetEntity` + dialog. |
| **OpenSnippetIntent** | "Open Snippet" | true | `snippet: SnippetEntity` | sets `AppIntentNavigator.shared.pendingOpenSnippetUUID`; ContentView opens it. No value. |
| **FindSnippetsIntent** | "Find Snippets" | false | `searchText: String?`, `collection: SnippetCollectionEntity?`, `favoritesOnly: Bool` (default false) | filters non-deleted snippets via `SnippetQueryFilter`. Returns `[SnippetEntity]` (chainable). |
| **ToggleFavoriteSnippetIntent** | "Toggle Snippet Favorite" | false | `snippet: SnippetEntity` | flips `isFavorite`, saves. Returns new state `Bool` + dialog. |

`CopySnippetIntent` mirrors in-app copy: increments `copyCount` (feeds
"Frequently Used"), does **not** bump `updatedAt` (avoids reordering the
gallery).

Parameter titles/prompts via `@Parameter(title:...)`. Each intent declares a
`parameterSummary` where it improves the Shortcuts editor readout.

## Navigation bridge

```swift
@MainActor @Observable
final class AppIntentNavigator {
    static let shared = AppIntentNavigator()
    var pendingOpenSnippetUUID: UUID?
}
```

- Injected into the SwiftUI environment by `SnippetsApp` (using `.shared`).
- `OpenSnippetIntent.perform()` sets `pendingOpenSnippetUUID`, then activates the
  app (foreground) — `openAppWhenRun = true` handles bringing the app forward.
- `ContentView` adds one `.onChange(of: navigator.pendingOpenSnippetUUID)`:
  resolve UUID -> snippet in `snippets`; if found, clear search, set
  `selectedSnippetID`, set an appropriate `sidebarSelectionContext`; then reset
  `pendingOpenSnippetUUID = nil`.

## Pure filtering logic (testable)

`SnippetQueryFilter` — a dependency-free `enum`/`struct` with static functions
operating on lightweight inputs (not SwiftData-bound where avoidable):

- `matches(title:description:language:query:)` — case-insensitive substring
  match mirroring `ContentView.matches`, used by both `entities(matching:)` and
  `FindSnippetsIntent`.
- A `filter` function taking `(snippets, query?, collectionUUID?, favoritesOnly)`
  and returning the matching subset. To keep it pure and testable, it operates
  over a small value projection of each snippet
  (`(title, description, language, isFavorite, collectionUUIDs)`), so tests need
  no `ModelContainer`.

The intents/query build that projection from `Snippet` models, call the pure
filter, then map back to entities.

## AppShortcuts

`SnippetsAppShortcuts: AppShortcutsProvider` with `appShortcuts` returning
`AppShortcut`s for the parameterless-friendly intents. Phrases include
`\(.applicationName)`, e.g.:

- "Create a snippet in \(.applicationName)"
- "Copy a snippet from \(.applicationName)"
- "Find snippets in \(.applicationName)"

Each `AppShortcut` gets a `systemImageName` and short/negative phrases as
appropriate. (`OpenSnippetIntent` and `ToggleFavoriteSnippetIntent` can also be
surfaced; `CopySnippetIntent`/`FindSnippetsIntent` are the primary voice
targets.)

## Testing

- **Unit tests** (TDD, `swift test`) for `SnippetQueryFilter`:
  - query matches title / description / language, case-insensitively;
  - empty/nil query returns all (subject to other filters);
  - `favoritesOnly` filters correctly;
  - `collectionUUID` membership filter;
  - combined criteria.
- The AppEntity/AppIntent glue is validated by the Xcode build (metadata
  generation + compile); no brittle runtime tests against the App Intents
  framework.

## Out of scope (YAGNI)

- Media items as entities.
- Deleting snippets/collections via intents (destructive; skip for now).
- Widgets / control-center controls / Focus filters.
- CloudKit-portable identifiers.
